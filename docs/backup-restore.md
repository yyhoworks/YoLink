# 手动加密备份与恢复

在「服务设置 → 备份与恢复」操作。备份包含 SQLite 应用数据、网盘凭据、播放与事件密钥、管理员密码校验资料，以及应用管理的迁移计划和 STRM 恢复副本。网盘中的媒体、外部输出挂载、Compose、环境变量和反向代理配置需要分别备份。

## 导出

输入当前管理员密码，再设置独立备份口令，生成并下载 `.age` 文件。口令为 12–1024 字节；请将文件和口令分别保存在其他设备。文件内含敏感凭据，口令丢失后无法找回。

应用使用一致的 SQLite 快照和 age 口令加密，不需要停服。每次仅允许一个备份或恢复操作。临时工作区需要容纳明文快照和加密文件；敏感快照在成功下载响应前清理。请求取消或进程退出后的未完成临时清理会在下一次操作或启动前重试；这不代表对存储介质进行安全擦除。

## 上传、确认和重启

恢复激活支持 Linux 的本地文件系统及本项目群晖容器部署，需要有效的文件/目录同步和同文件系统替换。Windows 可导出，管理页会禁用恢复激活。

1. 上传 `.age`，输入该备份的口令和当前管理员密码。此时只做隔离校验并保存候选，运行数据尚未替换。
2. 核对候选的账号、规则、输出登记数量、载荷大小和校验时间。输入 `RESTORE` 并确认该候选。
3. 输入 `RESTART` 重启。启动过程会保留完整原数据基线，再替换应用管理的数据。恢复后使用**备份中的管理员密码**重新登录。
4. 核对账号、规则、服务地址和输出映射，可显式执行只读连接检查及播放诊断。外部输出文件不会随应用数据回到历史版本，需要单独核对。
5. 输入 `REVIEWED` 完成核对，再重启一次。历史任务不会自动重放；定时规则、事件接入及待发通知保持暂停，按需逐项重新启用。

最多 10 万个文件、10 万个不同父目录，单文件 2 GiB，总载荷 4 GiB。恢复需要额外容纳候选、原数据副本、写入临时文件和物理回退空间预留；历史恢复会话也会保留。磁盘不足会拒绝继续或在保留基线的情况下进入恢复保护。不要手工删除正在使用的 `.restore-control` 或 `.backup-work` 文件。

页面显示网络异常或「结果未确认」时，先刷新恢复状态；请求可能已被接收，不要直接重复提交。重启可能中断当前连接，重新登录后继续查看状态。并发状态读取在备份占用操作锁时会提示稍后重试。

## 取消和回退

尚未开始替换时可以移除候选或取消等待中的恢复。恢复完成后，可在相同会话中输入 `ROLLBACK` 请求回退，再重启。手动回退先完整保留当前应用数据，随后恢复本会话的原基线；两套数据不会自动合并，外部输出文件保持原样。

若无法登录或数据库无法正常启动，先停止主服务并保留整个数据目录，再使用**同版本镜像**执行管理命令。以当前 Compose 为例：

```sh
docker compose stop yolink
docker compose run --rm --no-deps yolink restore-rollback
docker compose up -d yolink
```

命令在打开业务数据库前执行，并受独占数据目录锁保护。不要与另一个运行中的 YoLink 共享数据目录。日志损坏、基线缺失或摘要不符时会拒绝继续并保留现场；不要绕过校验、混用密钥或让旧版程序直接打开新数据库。

历史恢复会话最多保留 65 层，达到上限后会拒绝新的恢复确认并保留当前服务和候选。整理历史前须另行保存一致的整个数据目录；本版不自动删除旧恢复资料。

测试覆盖进程中断和注入的同步/写入失败。隔离容器和 tmpfs 满盘测试不能证明硬件断电、损坏磁盘或所有网络文件系统的可靠性。生产升级仍应单独准备停服一致备份和匹配版本的可执行回退。
